3. FILE: backend/enterprise/views.py
   CHANGES:
   - Added ADMS Protocol Endpoints (Device ↔ Server):
     
     a) adms_cdata(request) - Device Handshake
        - URL: GET /iclock/cdata?SN=<serial>
        - CSRF exempt
        - Auto-registers device if not exists
        - Updates last_seen_at
        - Returns: "GET OPTION FROM: <serial>"
     
     b) adms_getrequest(request) - Command Polling
        - URL: GET /iclock/getrequest?SN=<serial>
        - CSRF exempt
        - Returns pending command in ADMS format
        - Returns: "C:42:DATA UPDATE USERINFO PIN=...\tName=...\t..."
        - Or returns: "OK" if no pending commands
     
     c) adms_devicecmd(request) - Command Acknowledgement
        - URL: POST /iclock/devicecmd?SN=<serial>
        - CSRF exempt
        - Parses command ID from request body
        - Marks command as 'done' in database
        - Returns: "OK"
   
   - Added DRF Endpoints (Frontend ↔ Server):
     
     a) CreateDeviceCommandAPIView
        - URL: POST /api/commands/
        - Auth: IsAuthenticated
        - Creates pending DeviceCommand
        - Returns: DeviceCommand JSON
     
     b) ListDevicesAPIView
        - URL: GET /api/devices/
        - Auth: IsAuthenticated
        - Returns all devices with status and last_seen_at
        - Sorted by -last_seen_at (newest first)

API ENDPOINTS SUMMARY
================================================================================

ADMS PROTOCOL ENDPOINTS (Device ↔ Server, Plain Text)
────────────────────────────────────────────────────
GET /iclock/cdata
  Query: SN=<serial_number>
  Response: "GET OPTION FROM: <serial>"
  Purpose: Device handshake and auto-registration
  
GET /iclock/getrequest
  Query: SN=<serial_number>
  Response: 
    - "C:<id>:DATA UPDATE USERINFO PIN=<pin>\tName=<name>\tPri=0\tPasswd=\tCard=\t"
    - "OK" (if no pending commands)
  Purpose: Device polls for pending commands
  
POST /iclock/devicecmd
  Query: SN=<serial_number>
  Body: "C:<command_id>:..."
  Response: "OK"
  Purpose: Device acknowledges command completion

DRF ENDPOINTS (Frontend ↔ Server, JSON)
───────────────────────────────────────
POST /api/commands/
  Auth: Required
  Body: { "device_serial_number": "ABC", "user_id": "1001", "name": "John" }
  Response: 201 + DeviceCommand JSON
  Purpose: Create pending command from frontend
  
GET /api/devices/
  Auth: Required
  Response: 200 + [BiometricDevice] JSON
  Purpose: List all devices with status

================================================================================
IMPORTANT NOTES
================================================================================

1. ADMS Format:
   - Uses tab separators (\t) between fields
   - Pin= prefix for user ID
   - Pri=0 for privilege level
   - Empty password and card fields (or populate as needed)

2. Device Serial Number:
   - Must be unique per device
   - Case-sensitive
   - Used as device identifier throughout system

3. Device Polling:
   - Devices typically poll every 30 seconds
   - Adjust threshold based on actual polling interval
   - "Online" = last_seen_at within 5 minutes (configurable)

4. Status Lifecycle:
   - pending → done (normal flow)
   - pending → failed (if device has error)
   - Once done, next poll gets next command

5. Network:
   - Device must reach your server directly
   - No proxy/bridge needed
   - HTTP/TCP-based (no special protocols)
